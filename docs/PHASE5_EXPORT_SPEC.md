# 📄 Phase 5 Specification: Publishing & Export Engine

## 1. Overview & Objectives
The **Publishing & Export Engine (Phase 5)** provides PyBI / Wiki-Forge with static, versioned, and reproducible document and data export capabilities. It transforms dynamic BI dashboards, semantic metrics, and Wiki-Forge knowledge pages into frozen artifacts (PDF, HTML, Markdown, CSV) backed by deterministic snapshot metadata and SHA-256 filter context hashes.

---

## 2. Architecture & Components

```
                    ┌─────────────────────────┐
                    │  FilterContext State    │
                    └────────────┬────────────┘
                                 │
                                 ▼
┌───────────────────┐    ┌───────────────┐    ┌─────────────────────┐
│  Export Request   │───►│ ContextBinder │───►│ Snapshot Generator  │
│ (PDF/HTML/MD/CSV) │    └───────────────┘    │ (SHA-256 FilterHash)│
└───────────────────┘                         └──────────┬──────────┘
                                                         │
                                                         ▼
┌───────────────────┐    ┌───────────────┐    ┌─────────────────────┐
│ Jinja2 Templates  │───►│ ExportEngine  │───►│  Output Artifacts   │
│ (HTML / Markdown) │    │ Orchestrator  │    │  & snapshot.json    │
└───────────────────┘    └───────────────┘    └─────────────────────┘
```

### Key Modules:
- **`pybi.export_engine.snapshot`**: Generates unique `export_id`s, ISO-8601 timestamps, and SHA-256 hashes of the active `FilterContext` to ensure complete traceability.
- **`pybi.export_engine.context_binder`**: Evaluates active filter context rules and injects `active_filters`, `where_clause`, and filtered data extracts into the export payload.
- **`pybi.export_engine.engine`**: Asynchronously coordinates background job execution, Jinja2 template rendering, WeasyPrint PDF conversion, CSV generation, and filesystem storage (`pybi_data/exports/<export_id>/`).
- **`pybi.export_engine.router`**: Exposes FastAPI endpoints for initiating exports, checking job status via polling, and downloading generated artifacts.

## 3. Snapshot Metadata Schema (`snapshot.json`)

Every export generated by PyBI creates an immutable `snapshot.json` metadata file stored alongside the exported artifact:

```json
{
  "export_id": "exp_a1b2c3d4e5f6",
  "timestamp": "2025-02-23T12:00:00.000000+00:00",
  "project_id": "sales_dashboard",
  "project_version": "1.0.0",
  "active_filters_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "active_filters": {
    "regional_sales.region": {
      "table": "regional_sales",
      "column": "region",
      "values": ["Europe", "North America"],
      "operator": "IN"
    }
  },
  "source_files_list": ["sales_data.csv"],
  "format": "pdf",
  "template_id": "report_dati.html",
  "ai_compilation_prompt": "Genera il Capitolo 2 usando solo fonti con indice di maturità > 80 e includi le metriche DAX del modello corrente"
}
```

## 4. REST API Reference

### 1. Submit Export Job
`POST /api/projects/{project_id}/export`

**Payload:**
```json
{
  "format": "pdf",
  "template_id": "report_dati.html",
  "filter_context": {
    "regional_sales.region": ["Europe"]
  },
  "ai_compilation_prompt": "Includi sintesi executive e trend regionali.",
  "payload": {
    "title": "Quarterly Sales Report",
    "widgets": []
  }
}
```

**Response:**
```json
{
  "export_id": "exp_a1b2c3d4e5f6",
  "status": "pending",
  "message": "Export job submitted successfully for project 'sales_dashboard'",
  "status_url": "/api/exports/exp_a1b2c3d4e5f6/status",
  "download_url": "/api/exports/exp_a1b2c3d4e5f6/download"
}
```

### 2. Check Job Status
`GET /api/exports/{export_id}/status`

**Response:**
```json
{
  "export_id": "exp_a1b2c3d4e5f6",
  "project_id": "sales_dashboard",
  "status": "completed",
  "progress": 100,
  "format": "pdf",
  "template_id": "report_dati.html",
  "snapshot": { ... },
  "file_path": "pybi_data/exports/exp_a1b2c3d4e5f6/export_exp_a1b2c3d4e5f6.pdf",
  "error": null
}
```

### 3. Download Artifact
`GET /api/exports/{export_id}/download`

Returns the binary or textual file stream (`.pdf`, `.html`, `.md`, `.csv`).

### 4. Shortcut Endpoints
- `POST /api/projects/{project_id}/export/pdf`: Triggers background PDF generation.
- `POST /api/projects/{project_id}/export/data`: Triggers background CSV extract generation.

## 5. Adding Custom Jinja2 Templates

To add a new template to the export engine:
1. Place your template file inside `pybi/export_engine/templates/` (e.g. `custom_report.html` or `thesis_template.md`).
2. Use standard Jinja2 syntax to reference available payload fields:
   - `{{ title }}`: Report title.
   - `{{ snapshot.export_id }}` / `{{ snapshot.active_filters_hash }}`: Metadata fields.
   - `{% for f in active_filters %}`: Iterates over active filter rules.
   - `{% for widget in widgets %}`: Iterates over layout widgets.
   - `{% for table_name, rows in tables.items() %}`: Iterates over filtered dataset tables.
3. Pass `template_id="custom_report.html"` when invoking the API or UI export dialog.

## 6. Example AI Compilation Prompt for End Users

When using the **AI-Assisted Compilation** feature, users can supply structured directives to guide document assembly:

**Example User Prompt:**
> "Genera il Capitolo 2 usando solo fonti con indice di maturità > 80 e includi le metriche DAX del modello corrente per la regione 'Lombardia'. Evidenzia le anomalie di margine e sintetizza le raccomandazioni in un elenco puntato."

The Export Engine serializes this directive into the `snapshot.json` metadata and injects it into template variables (`ai_compilation_prompt`), making AI reasoning reproducible and audit-ready.
